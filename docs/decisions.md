your sign-off; `accepted` = we build on it; `open` = genuinely undecided and blocking something.

## Language (D20): Python for v1

**Decision: Python 3.12+.** Rationale:

- Everything BenchDiff does is glue: subprocess, files, TOML, regex, git, later HTTP to Ollama.
  Python is the shortest path to all of it.
- The statistics we need — median, IQR, bootstrap CI — are ~150 lines, not a `scipy` dependency.
- Learning Go *while* designing the pipeline means the language sets the pace, not the problem.
  The interesting part of this project is the orchestration and the honesty rules; a new runtime
  would compete with that for your attention.
- Distribution is `uv tool install benchdiff` / `pipx install benchdiff`, which is normal for dev
  CLIs. The single-binary advantage only matters once strangers are installing it.

**What we give up:** no single-file binary, ~80ms startup, weaker "systems tool" signal on a CV.

**How we keep Go on the table:** the core does no I/O outside a thin boundary. `Resolve`, `Extract`,
`Analyse` and `Render` are pure functions over dataclasses; only `Materialise` and `Execute` touch
the OS. A port later rewrites two modules, not the tool.

**When to revisit:** after v1 demos. Either port the executor to Go as a deliberate learning
project, or leave it — Python is not a weakness in a tool whose job is orchestration.

**Override clause:** if learning Go is itself a goal for this project, that is legitimate — but do
it *after* v1 exists, on the isolated Docker/macro work, not as the foundation. Otherwise the risk
is that the language becomes the project and BenchDiff never ships.

## Open: who is the first user?

If BenchDiff is primarily a **portfolio/CV artifact**, v1 (`optimize` + honest report) is the whole
game, and phases 7–10 are optional polish.

If it is primarily a **tool you will actually run on the legacy monolith**, then `macro` (phase 10)
matters far more, Docker moves earlier, and the report layer needs p99/RPS/saturation metrics from
day one — which changes `run.json`'s schema before we freeze it.

This answer decides the phase order. It does not change v1's design.

## Rejected outright

- **`git stash` + `git checkout` orchestration** from the draft: `git stash save` is deprecated,
  `stash pop` can conflict with a restored branch, and a hard crash strands the user in a detached
  HEAD. Worktrees have no such state.
- **"Deterministic benchmarking" as a claim**: orchestration is deterministic; timings are not. Say
  the true thing.
- **AI intent classification as the first pipeline step**: non-deterministic branch on the critical
  path, and a wrong classification silently runs the wrong benchmark.
